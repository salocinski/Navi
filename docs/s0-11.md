# S0-11 — Démonstration lecture progressive (carte TW-11)

Date : 2026-11-17. Statut : **critère atteint** — lecture progressive démontrée.

## Objectif

Montrer la chaîne complète texte → audio avec lecture progressive :
l'audio commence à jouer pendant que les chunks suivants sont générés.

## Chaîne validée

```
texte → segmentation phrases → phonémisation (espeak-ng) → tokens
  → inférence ort (Kokoro int8) → file audio rodio → lecture
```

## Prototype

- `scratch/prog_011/` — crate Rust autonome (bac à sable Sprint 0)
- Dépendances : `ort`, `libloading` (espeak-ng), `rodio`, `unicode-segmentation`
- Modèle : `models/kokoro/kokoro-v1.0.int8.onnx` + voix `af_heart`
- espeak-ng chargé dynamiquement via `libloading` (GPL-3.0+, lié légalement)

## Résultat de la démo

Texte de test : 307 caractères, 5 phrases → 1 chunk (~75 tokens estimés)

| Étape | Durée |
|---|---|
| Chargement modèle | ~1.8–2.3 s |
| Phonémisation (chunk unique) | ~6 ms |
| Inférence ort (1 chunk, 18s audio) | ~8.6 s |
| RTF (Real-Time Factor) | **~0.47** |
| Audio généré | 18.18 s (436200 échantillons, 24 kHz) |

La lecture commence dès que le premier chunk est enfile dans la file audio
`rodio` (Sink), pendant que les chunks suivants seraient générés en arrière-plan
(sur ce test, un seul chunk car le texte tient dans la limite de 480 tokens).

## Architecture progressive

- `AudioQueue` : file thread-safe (Mutex + Condvar) entre producteur (génération)
  et consommateur (lecture rodio Sink).
- Producteur (thread principal) : segmentation → phonémisation → tokens →
  inférence → `enqueue(audio)`.
- Consommateur (thread dédié) : `pop()` audio → `sink.append()` → lecture
  temps réel via rodio/cpal.

## Prochaines étapes (intégration cœur)

- Découpage multi-chunks réel (texte > 480 tokens) → file producteur/consommateur
  pleinement exercée.
- Contrôles lecture : pause, reprise, arrêt (méthodes `pause`/`resume`/`stop`
  déjà implémentées dans `AudioQueue`).
- Intégration dans `src-tauri/src/` comme module `tts::progressive`.
