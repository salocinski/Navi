# S0-13 — Sauvegarde/restauration presse-papiers (carte TW-13)

Date : 2026-11-17. Statut : **exploré, complexité API windows crate** — prototype partiel.

## Objectif

Sauvegarder le contenu complet du presse-papiers (tous formats) avant capture,
puis le restaurer après — pour ne pas perturber le presse-papiers utilisateur.

## Ce qui a été exploré

### API Windows requise
1. **Snapshot** : `OpenClipboard` → `EnumClipboardFormats` → `GetClipboardData` → `GlobalLock`/`GlobalSize` → copie raw bytes → `GlobalUnlock` → `CloseClipboard`
2. **Restauration** : `OpenClipboard` → `EmptyClipboard` → pour chaque format : `GlobalAlloc(GMEM_MOVEABLE)` → `GlobalLock` → copy bytes → `GlobalUnlock` → `SetClipboardData` → `CloseClipboard`

### Complexité rencontrée avec `windows` crate 0.58
- **Types `Result` partout** : `GlobalAlloc`/`GlobalLock`/`GlobalSize`/`GlobalUnlock`/`SetClipboardData` retournent tous `Result<T, Error>` — il faut `?` ou `.unwrap()` à chaque appel
- **`HGLOBAL` ≠ `HANDLE`** : `SetClipboardData` attend un `Param<HANDLE>`, mais `HGLOBAL` n'implémente pas `Param<HANDLE>` → cast manuel requis (`HGLOBAL(hglobal.0)` puis cast vers `HANDLE`)
- **`GlobalFree` n'existe pas** dans `windows::Win32::System::Memory` (remplacé par `GlobalSize` pour cleanup ?)
- **`Result<HGLOBAL, Error>`** ne s'utilise pas directement dans `GlobalLock`/`GlobalUnlock` — il faut `.unwrap()` ou `?` AVANT de passer à ces fonctions
- Pas de `GlobalFree` → nettoyage mémoire non trivial si échec partiel

### Prototype partiel (`scratch/clip_013/`)
Le code compile mais la restauration n'est pas totalement validée à cause des cast `HGLOBAL` → `HANDLE` pour `SetClipboardData`.

## Capture (#12) : FONCTIONNE
La **capture seule** (sans restauration) est **opérationnelle et validée** :
- `WM_COPY` → `OpenClipboard` → énumération formats → lecture Unicode/ANSI/HTML/RTF
- Test réel : 176 chars capturés, formats détectés (Unicode, ANSI, HTML Format, formats internes Chromium)

## Décision

**La capture (#12) est suffisante pour le Sprint 0.**
La sauvegarde/restauration est un **polish UX** (éviter d'écraser le presse-papiers utilisateur) — reporté au Sprint 1.

Pour le Sprint 0, on accepte que la capture écrase le presse-papiers (comportement standard de `Ctrl+C` de toute façon).

- Tester restauration complète sur formats HTML/RTF complexes
